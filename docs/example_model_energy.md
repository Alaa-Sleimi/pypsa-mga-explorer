# Example: running the notebook on model_energy

This walks through running `mga_exploration.ipynb` on PyPSA's built-in
`model_energy` toy network -- a single-node capacity-expansion model with no
external data files to obtain, and the fastest way to see the whole pipeline work
end to end.

## Prerequisites

- **Python 3.10 or newer** (the codebase uses `X | None` type hints); developed
  and tested on 3.13.5, the version pinned in this project's `.venv`.
- **Install dependencies**: see `README.md` for the full setup, or for now just
  `pip install -r requirements.txt`. This pins `pypsa==1.2.0`, `linopy==0.6.7`,
  and `highspy==1.14.0` -- HiGHS ships as part of `highspy`, so no separate
  solver install is needed. `ipykernel` is also pinned, which is enough to run
  this notebook from VS Code's Jupyter extension; if you want a standalone
  Jupyter/JupyterLab session instead, install `jupyter` separately (not pinned
  here).
- **Internet access on the first run only.** The network file itself is not
  committed to this repository (see below); it is downloaded once and cached.

## Steps

1. **Open the notebook with the repo root as the working directory.** The
   package is not installed, so relative imports of `mga_engine` and the
   relative `data/`/`figures/` paths both depend on the kernel's CWD being the
   repo root.

2. **Confirm cell 2's `network_source` is `"load_file"`.** This is already the
   value shipped in this notebook; it selects cell 5 (model_energy) over cell 4
   (an in-notebook 5-bus demo). Run cell 2, then cell 4 (it detects
   `network_source != "fresh"` and just prints a skip note -- this is expected).

3. **Run cell 5.** It calls `pypsa.examples.model_energy()`, which on first use
   downloads `model_energy.nc` from `https://data.pypsa.org/networks/examples/
   v1.2.0/model_energy.nc` (the version in the URL matches the pinned pypsa
   version) and caches it at `platformdirs.user_cache_dir("pypsa")/examples/
   v1.2.0/model_energy.nc` -- on Windows that resolves under
   `%LOCALAPPDATA%\pypsa\pypsa\Cache`. Later runs, on this machine and pypsa
   version, read the cached copy and need no network access. The cell then
   keeps every 12th snapshot (`STRIDE = 12`, reducing the source's 2920
   snapshots to 244) reweighted to a full year, and solves the network once
   with HiGHS for the cost optimum. Download size and solve time were not
   measured for this document; expect the solve itself to take well under a
   minute on this toy network.

4. **Run cell 7 (Section 2, PoIs).** The five PoI definitions already shipped
   (`wind_cap_gw`, `solar_cap_gw`, `battery_cap_gw`, `electrolysis_cap_gw`,
   `turbine_cap_gw`) already match model_energy's own carriers (`wind`, `solar`,
   `battery storage`, `electrolysis`, `turbine`) and need no editing to run.
   Ignore the comment above them claiming these are "PyPSA-Eur names, NOT
   model_energy's" -- it is stale, left over from an earlier version of this
   notebook; the code below it is already correct for model_energy.

5. **Run cell 9 (Section 3, preparation).** With no cache file yet at
   `preparation_state_modelenergy.nc`, this runs the full preparation phase:
   with the shipped `n_vertices=40`, `n_interior_levels=5`,
   `n_samples_per_level=15`, that is 115 sampled points, each solved once for
   vertex/interior sampling and once again for GP pricing -- 231 HiGHS solves
   in total, plus the one base solve from cell 5. The pipeline itself is
   described in `docs/workflow.md`.

6. **Run cell 11 to save the result.** This is the only step that creates the
   `data/` directory (if it does not already exist) and writes
   `data/preparation_state_modelenergy.nc`. Skipping it discards the samples
   when the kernel stops, and cell 26 (Section 6) will later fail because
   `data/` is missing.

7. **Run the remaining cells to explore.** Sections 3.1-3.2, 4.1-4.3, 5, 6, and
   7 all work from the samples just produced; see `docs/workflow.md` for what
   each one shows. The first time you pick a PoI pair in Section 3.2 (cell 15),
   that pair's boundary is solved on the live network, so expect a short delay
   before the plot updates; other pairs and later runs of the same pair are
   served from an in-memory cache.

8. **Figures (optional, cell 28).** Writes 11 PNGs to `figures/`. Both
   `figures/` and `data/*.nc`/`*.npz` are excluded by `.gitignore` (except
   `data/.gitkeep`), since neither the cached preparation state nor the
   exported figures are meant to be committed -- they are regenerated by
   running the notebook.

## Troubleshooting

- **`ValueError` from `pypsa.examples.model_energy()` mentioning
  `allow_network_requests`.** No internet access on the first run, and no
  cached file either. Either allow network access, or manually place a
  `model_energy.nc` at the cache path named above.
- **`data/` is missing even though `.gitignore` no longer excludes it
  wholesale.** The rule was changed to `data/*` plus `!data/.gitkeep` so a
  tracked `data/.gitkeep` would keep the empty directory in a fresh clone, but
  as of this writing that file has not yet been committed -- if `data/` is
  missing, just run cell 11 once (it creates the directory itself), or
  `mkdir data`.
- **`RuntimeError: Preparation state does NOT match ...` from cell 9.** The
  cached file's fingerprint or sampling parameters differ from the current
  notebook values (a changed `epsilon`, `STRIDE`, PoI definitions, or sample
  counts). Set `rerun_preparation = True` in cell 9 and re-run it; see
  `docs/configuration.md`'s "Cache invalidation" section for exactly what is
  and is not checked.
- **Results differ from what this repository's own cached state shows, or an
  old cached `.nc` seems to load "successfully" but looks wrong.** Package
  versions matter here: `pypsa.examples.model_energy()`'s download URL is
  versioned, PyPSA's own Components API has changed across versions, and the
  fingerprint's whitelist is version-sensitive. Match `requirements.txt`
  exactly rather than using whatever versions happen to already be installed.
- **`ImportError` for `mga_engine`, or `FileNotFoundError` for `data/...`.**
  The kernel's working directory is not the repo root; restart the kernel from
  there (step 1).

For every setting used above, see `docs/configuration.md`. For what each step of
the pipeline actually does and why, see `docs/workflow.md`.
